# Accio Work 知识库演示

Accio Work PRD「知识库构建与管理」「检索链路」与前台知识问答的可运行原型。

- **入库**：上传文档或抓取网页 → 解析 → 按知识类型切块 / 抽取表格 / 抽取问答 → 敏感信息检查 → 向量化 → 建索引。
- **检索**：检索测试页逐层查看标准问答匹配、表格精确查询，以及 RAG 的召回、融合、重排和最终结果。
- **前台问答**：在 Accio Work 工作台界面（`web/`）向单个专家提问，按检索结果直答、请用户选择、依据作答或回复无依据，回答带来源。

向量化、重排与作答调用阿里云百炼的真实模型。

## 和 PRD 的对应关系

| 功能 | 演示实现 | PRD 章节 |
|-|-|-|
| 知识分层 | 平台公共知识层（平台规则库、帮助中心）、企业私域知识层（企业团队库）、个人知识层（个人知识库） | 知识底座分层 |
| 文档解析 | PDF（带页码）、Word（标题与表格）、Excel / CSV、Markdown、TXT、网页统一转为 Markdown | 文件解析 |
| 分块 | 6 种文本知识类型各用一种规则：规则类按条款切子块并保留父块；帮助文档 500 / 重叠 50；商品手册 800 / 重叠 100；说明表格每 20 行带表头；问答整条；案例按阶段 | 3.3 分块规则、3.4 父子块 |
| 结构化表格 | 商品目录、价格表、运价表、成本表按表头同义词映射为标准字段，逐行入库。商品目录每个 SKU 生成一条描述块参与语义检索；价格类只做精确查询，过期行自动排除 | 结构化数据路径 |
| 标准问答库 | 从「Q： / 相似问： / A：」或「标准问 / 相似问 / 答案」表格抽取。每条问法单独向量化；单条 ≥0.85 直答；多条 ≥0.85 时，差值 ≥0.03 取第一，否则请用户选择；0.70–0.85 给「你是不是想问」并走 RAG | 6.3 QA 库 |
| 网页抓取 | 单页 / 站点地图 / 目录页，单次最多 30 页，遵守 robots.txt；按正文哈希判断变化，只为变化的页面生成新版本；无正文页面记为缺口 | 更新策略 |
| 向量化 | `text-embedding-v4`，1024 维，每批 10 条 | Embedding 选型 |
| 元数据 | 知识空间、知识类型、表格类别、来源类型、来源网址、权限级别、可见部门、审核状态、个人信息等级、处理位置策略、业务域、平台、目标市场、语言、质量等级、风险等级、生效 / 失效时间、效力状态、内容哈希、原文定位、父块 ID | 6.2 元数据构建 |
| 权限 | 公开 / 平台内部 / 企业全员 / 指定部门 / 仅本人。权限继承知识空间可选范围，只能调严；检索前按身份与部门过滤 | 10.1 权限分级 |
| 审核 | 平台公共知识入库为「待审核」，审核通过才参与检索；新版本审核通过前旧版本继续生效 | 审核与发布 |
| 敏感信息 | 身份证号、银行卡号 → `local_only`，不发往云端向量化。企业与个人知识中的手机号、邮箱 → 个人信息等级「高」，面向买家的接待身份不可见 | 6.2.3 处理位置策略 |
| 版本与去重 | 同一空间内同名文件（网页按网址）生成新版本，旧版本标记为「已被替代」；内容完全相同的文件不重复入库 | 6.2.2 效力状态 |
| 检索 | 关键词（BM25）与向量各召回 30 条 → RRF 融合 30 条 → `qwen3-rerank` 重排 → 相关分 ≥ 0.5 → 最多 5 条 → 子块命中回填父块 | 8.2 Rerank、检索链路 |
| 兜底 | 重排报错或超过 2 秒未返回时，返回融合排序前 5 条并标记「未经重排」；全部低于阈值时返回「知识库无依据」 | 8.2 Rerank |
| 前台作答 | 标准问答直答时原样返回答案；问答差值 <0.03 时请用户选择；其余情况把表格行与最终片段（子块换成父块）交给 `qwen-plus` 作答。回答先给结论，逐句标注来源，价格注明币种、数量段和生效日期；只列原始数值，出现算式时要求重写一次，仍有算式则改为只给数据和报价工具指引；无依据时引导到帮助中心与客服；面向买家的身份不展示被过滤的文档名 | 11.10 产品问答检索链路 |

## 运行

需要 Python 3.10+、Node 18+ 和一个[阿里云百炼](https://bailian.console.aliyun.com) API Key。

```bash
# 后端
cd backend
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # 填入 DASHSCOPE_API_KEY
uvicorn app.main:app --port 8000

# 前端（另开终端）
cd frontend
npm install
npm run dev                 # 知识库后台 http://localhost:5173

# 前台工作台（另开终端，无需安装依赖）
cd web
npm start                   # http://localhost:4174
```

前台只有单专家对话接入后端：在首页选一个专家发出问题，之后可在同一对话里继续追问；侧栏里的历史会话和专家团对话仍是预设演示。对话顶部可切换提问身份。

项目放在 iCloud 同步目录（如「文稿」）且开启了「优化 Mac 存储空间」时，`venv` 和 `node_modules` 可能被转存到云端，启动会极慢或读取超时。可以把这两个目录建在同步目录之外，再用软链接放回原位置。

`samples/` 里的示例文档均为虚构：

| 文件 | 上传时选择 |
|-|-|
| 示例_平台商品发布规则.md | 平台规则库 / 平台规则 |
| 示例_产品帮助FAQ.md | 帮助中心 / 标准问答 |
| 示例_商品目录.csv | 企业团队库 / 数据表格 / 商品目录 |
| 示例_价格表.xlsx（含 1 行已过期价格） | 企业团队库 / 数据表格 / 价格表 |
| 示例_运价表.csv | 企业团队库 / 数据表格 / 运价表 |
| 示例_销售部客户跟进SOP.md（含手机号） | 企业团队库 / 平台规则 / 指定部门：销售部 |

可以试的问题：

- 「积分怎么计算」：标准问答直答
- 「TB-1001 发美国的价格和运费」：表格精确查询
- 「儿童玩具上架要什么证书」：RAG 命中规则条款
- 「大单折扣需要谁批」：切换为李四或 AI 接待助手后，看不到销售部文档

## 目录

```
backend/app/
  parse.py     文件 → Markdown；表格原始行读取
  chunk.py     按知识类型切块
  tables.py    数据表格字段映射与抽取
  qa.py        标准问答抽取与匹配判定
  ingest.py    入库流水线、审核、删除、重新向量化
  crawl.py     网页抓取与变化检测
  bailian.py   百炼向量化与重排接口
  meta.py      元数据取值、知识空间、检索身份
  store.py     SQLite 存储
  search.py    过滤、问答匹配、表格查询、混合召回、RRF、重排、阈值、父块回填
  main.py      HTTP 接口
frontend/src/pages/
  DocList.jsx    文档管理、上传与审核
  DocDetail.jsx  元数据、处理记录、切块 / 表格 / 问答结果
  Crawl.jsx      网页抓取来源与同步结果
  SearchTest.jsx 检索测试
```
